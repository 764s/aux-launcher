# 辅助启动器痛点文档 · 记忆历史选择

## 背景与核心痛点

在实际使用中，需要通过非 TUN 模式经代理启动的软件通常是固定的一个或少数几个。

如果每次打开启动器都回到空白初始态，用户必须反复经历「点击选择 → 层层浏览目录 → 找到同一个 `.exe` → 启动」的重复流程。这种机械寻路直接削弱了启动器“轻量、即开即用”的核心价值。

## 易用性诉求

1. **打开即用（记忆上次选择）**
   - 启动器记住用户最近一次成功选定的目标程序。
   - 下次打开时直接恢复该选择，用户无需重新定位文件，一步即可点击启动。

2. **一键切换常用程序（记忆少量历史选择）**
   - 用户往往不止一个需要走代理的软件，启动器应记住近期选过的少量程序。
   - 允许用户在主界面直接点击切换，不必再次打开系统文件选择对话框。

3. **允许按需遗忘（轻量管理）**
   - 并非所有曾选过的程序都值得长期保留（例如临时测试用的 `.exe`）。
   - 用户应能随手移除某条不再需要的记忆记录，保持常用项干净。

4. **记忆失效时的容错**
   - 若已记住的 `.exe` 已被移动、重命名或删除，启动器应明确提示目标文件不可用，阻止无效启动，并引导用户重新选择、切换其他记录或移除该失效项。

## 极简边界约束

- **静默记忆，零配置门槛**：自动记录用户选择，不引入独立的“设置页”“历史管理弹窗”或“是否记住本次选择”等额外开关。
- **数量克制**：仅保留最近常用的极少数记录（建议最多展示 3~4 项），避免界面演变为臃肿的应用列表。
- **不干扰运行态**：目标程序处于启动准备或代理运行期间，锁定历史切换，防止误操作导致界面状态与当前受管会话不一致。
- **不改变核心路径**：当不存在历史记录（如首次使用或已全部清除）时，界面完整回归最纯粹的「选择 `.exe` → 经代理启动」初始形态。
